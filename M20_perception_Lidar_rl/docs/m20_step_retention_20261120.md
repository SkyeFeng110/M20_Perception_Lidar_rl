## 为什么旧保护没保住后期能力

代码可确认，旧 StepSupport 的教师仍为 35300，回放也来自它；这不能直接保护后来在 47900 才出现的成功逐阶动作。旧前腿上楼约束弱，全网 PPO 更新可逐渐改变这些动作。旧 MuJoCo 验收负责记录失败、允许继续训练，没有独立保留和比较已获得能力的选择机制。

旧日志中 `Loss/reference_anchor` 从 47900 附近约 .00170 降到 50900 附近约 .00157，但部署逐阶与偏航明显变差。这说明对旧教师更接近，不能代表对新能力保持更好。

同期腿/轮最小标准差约从 .239/.490 变为 .231/.484，仍高于 .18/.35 的下限；不能把本次退化主要归因于探索方差塌缩。奖励总和、训练地形分布与固定部署工况不同，也不能用训练均值走势替代 MuJoCo 行为结果。上述是证据支持的机制缺口，没有训练消融证明各因素的独立贡献。

## 减少遗忘的三项训练改动

1. **成功动作回放保护**：教师明确换成 47900，重新生成与该权重 hash 对应的 6053 条部署观测。只从 7 个真实成功上楼工况的 moving 阶段取成功动作，按工况均衡采样。软保护前腿 hipy/knee，后腿权重为其一半，并保留平均轮驱动；目标是运动中的成功动作，静止不会满足保护目标。
2. **每次 PPO 更新的动作均值约束**：从当轮 rollout 取状态，在更新前保存均值与标准差。各 minibatch 用固定旧标准差计算均值 KL 软约束，减少单次累计漂移，不能通过增大方差掩盖均值变化。起始学习率 5e-6、每次更新 2 epochs；保留全 Actor 可训练和探索下限。
3. **真实退化反馈**：每 100 次更新做 MuJoCo 评测，逐工况同时比较起点 47900 与当前最佳。出现新增跌倒、停滞、逐阶丢失、到顶丢失或速度/偏航/横移退化时，成功保护系数乘 1.25（最高 4），学习率乘 .8（最低 2e-6）。有效行为失败继续训练，不回滚、不冻结；运行错误和资源错误仍按错误处理。

为允许修正教师右偏，通用教师约束只保留运动时的四轮平均驱动，成功动作约束也释放 hipx 与左右轮差速。50% 成功样本进行观测和原成功目标同步镜像，不在镜像状态重新查询带偏置的教师。原有镜像等变目标还扩展到当前直行 rollout 状态。

这些是软约束，不是行为不退化的数学保证。尤其本阶段教师固定为 47900：未来更优动作会被归档，但不会自动生成新的成功回放并替换教师。当前 rollout 局部约束减少后续漂移，新增能力的长期保持仍需看连续实测；若要把后来获得的新步态转为下一阶段教师，需要重新生成物理证据和配套回放。

## 修正右偏与避免“少动少错”

新增权重 .75 的正向路线奖励：实际沿路径前进比例乘以航向、横向位置、偏航角速度和横向速度的质量项。左右误差对称，静止或后退得零分，已经偏离路线仍能通过继续前进获得正收益。用仿真世界状态与命令原生 `v11_path_heading_w` / `v11_path_origin_w` 计算，只作用于上楼直行且离开 B1 入口附近的阶段。

原生速度/前进奖励持续有效，漏阶后也不关闭；没有加重跳阶成本、没有全段减速、没有把成功动作目标改成零。保留此前支撑信用和降噪目标。Actor 输入仍为 63 维、输出仍为 16 维，未增加真实足端传感输入，全部学生 Actor 参数可训练；冻结的是参考教师。

## 最佳候选与续训

训练状态可以继续探索；部署候选独立选择。每个候选必须保住已完成工况的逐阶与到顶，不能新增跌倒、绕行、起步失败或停滞。偏航容差 +3°、C 后静止偏航 +1°、横移 +.10 m，速度至少保持 `.9 * min(参考速度, 命令速度)`，平地伸腿指标恶化最多 .01 m。同时与种子和当前最佳比较，避免容差逐次累积到种子以外。

候选按逐阶完整数、漏阶数、速度/偏航/横移/平地姿态误差排序。通过全部保持条件且排名更优才晋级，按 hash 保存权重、参数、结果和物理 manifest。`best_candidate.json` 与最新训练权重分开，`fully_accepted` 只取严格最终验收结果，47900 不会被假标为全部修复。

真实历史回放检查已证实：50900 的 1/8 逐阶、偏航变差、停滞和跌倒使其不能替换 47900。

每次评测后另存训练日志目录中的 `resume_after_eval.pt`，保存最新学习率、保护倍数、优化器、课程进度及已测最佳候选位置。原先被测的 `model_N.pt` 文件不会被重写，hash 与物理证据保持对应。续训会恢复并重新归档最佳候选，继续保护其已获得能力，而非重置为种子排名。续训依赖原最佳归档资产仍可访问。

## 用户手动启动

从仓库根目录执行：

```bash
cd M20_perception_Lidar_rl
M20_PYTHON=/home/arcus/miniconda3/envs/isaaclab/bin/python \
bash scripts/train_m20_v111_guarded.sh \
  --step-retention \
  --num_envs 4096 \
  --total-updates 50000 \
  --baseline-results data/m20_recovery/baseline_v2/results_with_acoustic_proxies.json \
  --output "artifacts/step_retention_from47900_50000_$(date +%Y%m%d_%H%M%S)"
```

用户后续明确要求新训练为 50000 轮，启动器的总更新上限已调整为 50000（不带参数时的默认值仍为 30000）。以上命令从 47900 网络初始化、使用新 Adam；`--total-updates 50000` 指追加 50000 次更新，最终索引约 97900。每次使用新的 output 目录；加 `--check-only` 仅预检。

若新阶段后来中断，使用该次训练日志中的 `resume_after_eval.pt` 保留完整优化器与保护状态，不要把它当成新目标初始化：

```bash
M20_PYTHON=/home/arcus/miniconda3/envs/isaaclab/bin/python \
bash scripts/train_m20_v111_guarded.sh \
  --step-retention \
  --resume-checkpoint /实际新训练日志目录/resume_after_eval.pt \
  --num_envs 4096 \
  --total-updates 剩余追加更新数 \
  --baseline-results data/m20_recovery/baseline_v2/results_with_acoustic_proxies.json \
  --output artifacts/step_retention_resume_新时间
```

续训从上次完整评测后的状态开始，尚未完成的那一段更新可能需要重做。原始 35300 结果继续作为独立旧能力验收基线；本阶段 47900 成功回放和最佳选择保护新增逐阶能力，这两个用途不同。
