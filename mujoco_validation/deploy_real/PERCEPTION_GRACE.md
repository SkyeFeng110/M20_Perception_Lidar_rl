# 短时感知缺失与策略连续运行

用户要求前雷达短时遮挡时维持现有策略，包括上下楼，持续缺失才退出。
唯一时长台账是 `perception_grace_limits.json`，由用户确认。

`apply_occlusion_grace.py` 只接受从1515取回并核验过的源码版本，在控制器停止时接线。
它将台账生成到硬件接口实际使用的观测存储，并同步修改策略输入检查和状态机。
发布前仍在同一存储锁下检查命令所用的租约与故障代次。

感知正常时保持既有当前/保留观测选择。缺少新的有效输入时，显式进入
`DegradedHold`，使用最近一次有效的当前地形观测；关节、IMU、遥控指令及动作历史
继续更新，策略持续生成新动作。不会重复发送一帧固定目标，也不将未知地形声明为平地。
来自更旧楼梯观测的保留几何不会被一帧新的有效零观测重新续期。

降级期限从最后有效源帧的测量时间计起，包含原有正常新鲜度窗口。
原始源身份、时间戳和实际观测年龄保留；`grace_deadline_s` 是单独的降级授权，
不是新的雷达测量时间。重复发布、无效消息和墙钟回退不能延长期限。
有效的新源帧恢复后采用其新观测；没有新源帧时，最终发布锁内也不能越过期限。

当前允许降级的显式无效事件是协议和身份完整的 `source_timeout`，以及完全没有新消息。
缺失有效观测前不能首次启用高增益状态。消息格式/契约错误、多发布者、来源重启、
夹具消息等仍按硬故障处理；所有既有关节与机体反馈保护继续独立生效。
超过期限仍锁存阻尼，恢复执行须经过原有恢复流程。

`perception_grace_test.cpp` 用虚拟时钟覆盖测量年龄、重复消息、恢复、期限及发布边界。
`perception_grace_worker_test.cpp` 编译掉所有硬件/UDP工厂，使用部署模型和真实RL工作线程，
检查正负台阶/零观测、降级期间遥控输入更新、持续推理、超时阻尼及硬故障。
无电机测试采用理想反馈，不能证明真实台阶上的动力学或遮挡期间的通行能力。

实际完成的构建、模型/控制器/台账哈希、现场是否启动及未验收项记录在
`PERCEPTION_GRACE_DEPLOYMENT_20261119.json`。保护模块的台账和ELF身份必须通过最终校验。
