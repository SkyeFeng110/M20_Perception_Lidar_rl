# 四膝误差代理阈值 85 Nm 与跟踪滞后核查

用户指定将四条腿 Knee 的位置误差代理阈值从 76.4 Nm 调整为 **85 Nm**。这是发布命令前的 `abs(q_target - q_feedback) * Kp` 软件准入门槛，不是电机总输出扭矩限制。当前 Kp=80，对应允许误差从 0.955 rad 调整为 1.0625 rad（约 60.88°）。SDK 关节索引为 2、6、10、14。

## 驱动端总扭矩限制

已只读核查 AOS 的 `/opt/robot/share` 配置、`/etc/robot`、ecanmaster / node_driver / mcu_update 文件、实际链接的 `libecanmaster.so`、SDK 头文件及近期服务日志。没有找到电机固件当前限流值，以及限流安培数换算输出轴扭矩的完整依据。因此 **当前驱动总扭矩限制尚未核实，也无法确认 85 Nm 在真实硬件安全范围内**。

SDK 存在 `kIndexSetLimitCurrent=11`、`kIndexGetConfig=24` 及 `Motor::ConfigMotor` 接口，但公开文件不足以解码当前配置并校验其物理含义。本轮没有实例化底层 Motor 对象抢占电机网口，也没有发配置指令或修改驱动限流。

训练配置和 URDF 中的 `effort_limit=76.4` 是模型配置依据，不能作为当前固件峰值或安全额定值的证明。位置误差代理也不包含完整的 D 项和前馈项；发布保护保留前馈限制，不能据此声称完整 PD 总输出被钳制在 76.4 Nm。

审计证据见 `artifacts/20261120/knee85/driver_config_audit.json`、`driver_deep_audit.json`、`driver_headers_read.json`、`driver_journal_limits.json`。
