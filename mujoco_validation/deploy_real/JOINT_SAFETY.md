# 关节命令保护与事故记录

适用范围是本仓库部署的自定义 AOS 控制器。厂商控制程序及驱动固件未修改。
本次新增保护必须经过重编译、无电机验证和 ELF 身份检查后才能通过启动入口。

## 发布前保护

`harden_native_release.py` 只接受审查过的最终部署清单。它把
`guarded_dds_publish.inc` 接到 `DdsInterface` 的共同发布入口，
`SetJointCommand` 和 `SetPolicyJointCommand` 都在此检查。
起立、趴下、策略控制与阻尼状态共享这个入口。
策略来源租约在拿到共同发布锁、完成目标检查之后重新判断，过期命令不会
因为等待发布锁而获得新的有效期，拒绝时也不会推进已发布目标或动作历史。

检查发生在 SDK→电机坐标转换之后：校验方向和零位参数，将实际待发消息
还原成 SDK 坐标，再执行边界判断。轮关节为连续转动，不套用腿关节角度范围。
控制字复位握手没有位置增益、速度目标或前馈力矩，不属于策略位置命令。

唯一数值台账是 `joint_safety_limits.json`。2026-11-19 用户要求参考本机
`deploy_real_ws` 的旧部署，当前直接采用旧版逐腿软件角度范围和速度限制。
左右髋及前后髋膝独立列出，不再与通用 SDK 左前腿范围取交集。
生成器输出编译常量，Idle、起立规划使用的前腿范围和最终发布保护均读取它。
策略发布前另加内侧边界余量与成功发布目标限速。
数值、接线、事故及验证边界见 [本次限位修正](REFERENCE_LIMITS_20261119.md)。
这些是软件范围，不代表已经实测确认了驱动器内部限位。

有限但越界、非有限、无效坐标映射、反馈失效等异常会拒绝该帧，并立即发布
零位置增益、零目标速度和零前馈力矩的阻尼命令。故障在进程内锁存；
来源恢复与正常策略输出不会清除关节命令故障。新的有效 R2 会先完全卸力、
归档并重启事故记录器，再清除锁存与目标历史；后续起立仍需新的 L1/L2。
停止、退出及被动命令不受这些运动条件阻挡。见 [R2 恢复说明](RECOVERY_FEATURES_20261119.md)。

变化率检查比较相邻**实际成功发布**的目标，首次激活比较目标与实测角。
暂停不会积累成任意大的跳变额度。目标与反馈的偏差还受位置增益对应的
软件误差代理预算约束；腿关节速度命令及前馈力矩也使用同一台账检查。
策略目标限速和最终目标变化率现均为 **50 rad/s**；这些目标变化率与速度命令限制分别设置。
2026-11-19 用户进一步指定四条腿的 HipX 统一使用 **0.65 rad** 偏差上限，
并保留 **52.0 Nm** 的位置误差代理量上限（Kp=80 时对应 0.65 rad）。
较高 Kp 不会获得更大的代理量额度；四条 HipY 现按用户要求采用 **95 Nm** 误差代理阈值，膝关节沿用原门限。
四个 HipX 的前馈力矩上限仍是 32.4 Nm，角度、反馈及
感知丢失 2 秒保护不变。部署状态与回放证据见
[四腿 HipX 修改记录](ALL_HIPX_TRACKING_20261119.md)。
这些阈值是软件保守门控，尚未完成真机步态适用性验收。
它们不能证明实际总 PD 力矩、碰撞力或驱动饱和响应与仿真一致。

## 常驻事故记录

正式启动器把独立记录器指向机器人持久化数据分区的
`/var/opt/robot/data/m20_joint_guard_incidents`。该路径不依赖电脑或 SSH，
也不依赖可选的 alignment/点云采集开关。绕过启动器而没有可用记录器时，
硬件接口拒绝初始化。

记录包含 SDK 实测关节角/速度/力矩、策略观测与原始/处理后动作、候选目标、
实际发布的电机命令、方向与偏置、状态与遥控输入、恢复请求序列、时间戳，
并关联模型和安全台账哈希。SDK 未提供的电流和驱动内部状态不据此推断。

生产者只向有界内存队列复制记录，格式化、轮转和同步在低优先级线程执行。
文件容量、磁盘余量、同步周期及故障后窗口均由数值台账确定。
记录器丢帧或 I/O 故障会使高增益命令被拒绝，阻尼仍可发送。

启动时 `SafeController::Start` 主动进入安全等待；这个阶段持续记录状态，
但不触发事故冻结。状态采样首次观察到安全输入就绪后，才将后续 SDK/遥控
安全停止认定为事故。关节命令故障在任何阶段都触发事故，不受启动等待豁免。
每条记录的 `fault_trigger` 明确标记是否触发事故冻结。

首次关节故障或就绪后的 SDK/遥控安全停止会保存独立的首次故障记录，并在保留故障后
窗口后冻结环形记录，防止持续阻尼覆盖事故数据。新的有效 R2 在卸力后将
旧环形文件和首次故障归档到 `incident_<session>/`，再开启新记录，无需重启控制进程。
真实 I/O 或磁盘故障仍禁止高增益输出；R2 的卸力输出仍可发送。
突然断电可能丢失尚未同步的尾部数据；限额或写入失败会明确标记不完整。

当前版本的感知超时锁存没有接入首次故障冻结。该类停止的环形记录仍会轮转，
需要及时手动归档并保留控制台日志。不能把没有 `first_fault.json` 当成没有感知故障。
2026-11-19 现场已正常起立，随后 `source_timeout` 触发阻尼；用户报告此前有人遮挡
前雷达。事后只读采样确认链路恢复，但没有同步原始数据证明遮挡首先影响了哪一级。
阻尼不维持站立位置；本轮未更改此故障响应。详细证据边界见修复记录 JSON。

取回文件后可在本机执行：

```bash
python3 mujoco_validation/deploy_real/summarize_incident.py /path/to/copied/incidents
```

该工具只读，报告环形覆盖、记录缺口、首次故障和是否正常结束。
`complete` 表示已写入记录的 I/O 状态，不表示保留了整个运行历史。

## 验证边界

纯逻辑测试对全部腿关节注入上下界越界、非有限值、目标跳变及反馈异常。
独立 DDS 测试编译掉实际命令发布器，使用实际 M20 坐标映射和共同发布入口，
验证通用状态路径、策略路径、提交结果与锁存。它不会启动运动控制。
记录器测试覆盖并发、轮转、真实写入失败、首次故障冻结和启动等待判定。
DDS 测试还验证两次冻结后的 R2 全零卸力、记录器重新启用及两份事故归档；
实际 FSM 测试验证感知/关节故障后可两次使用新的 R2、L1、L2 恢复。
实际DDS接口的无电机测试还覆盖启动等待之后提交通用起立命令的路径。
`replay_joint_guard_pose.cpp` 用本次真机记录的 SDK 角度重放最终保护类，
对比更正前后的趴姿边界检查。这个静态回放将速度、力矩置零，不是实际起立动力学验证。

以上是软件验证。上下楼后平地姿态、真实零位/方向、驱动实际限位、
力矩和速度限制、超限响应仍需现场验收；既有事故原因仍未确定。
